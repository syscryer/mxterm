# 复制连接技术设计

## 设计目标

在不增加独立页面、第三方依赖或通用复制框架的前提下，复用现有连接弹窗和 `connection_upsert` 保存链路，实现保存前不落库、保存后得到独立副本的连接复制能力。

## 前端交互

1. `ConnectionPane` 的连接树叶子节点增加 `onDuplicate` 回调，并在“编辑连接”之后渲染带 Lucide `Copy` 图标的“复制连接”菜单项。
2. `WorkspaceShell` 记录当前弹窗处于新建、编辑或复制模式。复制入口继续使用延迟加载的 `ConnectionDialog`，不把弹窗模块静态合入启动首屏。
3. 复制模式向 `ConnectionDialog` 传入原连接作为预填来源，同时显式标识复制模式，避免继续用“是否存在 connection”推断编辑语义。
4. 弹窗标题显示“复制连接”，主按钮显示“创建副本”，不显示删除按钮和删除确认框。
5. 复制表单通过现有 `formFromConnection` 生成，并做以下调整：
   - 清除 `id`，保证保存时创建新连接。
   - 设置 `source_connection_id` 为原连接 ID，供后端复制安全存储中的内联秘密。
   - 默认名称使用“原名称 - 副本”；若名称已存在，依次使用“原名称 - 副本 (2)”“原名称 - 副本 (3)”。
   - 清除收藏、最近连接时间和远端系统探测字段。
6. 用户关闭弹窗时只清理本地表单状态，不调用保存接口，因此不会产生副本。

## 保存契约

为现有 `ConnectionProfileInput` 增加仅用于创建副本的可选字段 `source_connection_id`。继续复用 `connection_upsert`，不新增单独的 Tauri 命令。

- 普通新建：`id` 和 `source_connection_id` 均为空，行为不变。
- 编辑：`id` 存在，`source_connection_id` 为空，行为不变。
- 复制：`id` 为空，`source_connection_id` 指向原连接。

后端仅在创建新连接且提供 `source_connection_id` 时读取源连接。源连接不存在时返回可恢复错误，不降级为空密码副本。

## 凭据处理

- `saved`：继续引用同一个保存账号 `credential_id`；账号本身仍由账号管理功能维护。
- `prompt`：复制认证模式，不持久化秘密。
- `inline`：若用户未在复制弹窗中修改密码或私钥口令，后端从源连接的秘密引用读取值，再以新连接 ID 写入独立的秘密槽位；若用户已修改，则保存用户输入的新秘密。
- 密码显示继续使用原连接 ID 调用现有 reveal 能力，并继续受 `allowPasswordReveal` 控制。
- 测试复制草稿时，后端使用 `source_connection_id` 解析未修改的内联秘密，行为与编辑原连接时一致。

副本与原连接拥有独立的连接记录和内联秘密槽位；后续修改或删除任一连接不会影响另一条连接。

## 数据与兼容性

- 不新增数据库列或迁移；`source_connection_id` 只存在于命令请求中。
- 不复制 `is_favorite`、`last_connected_at`、`remote_os_id`、`remote_os_name`、`remote_os_version`。
- 协议、主机、端口、用户名、分组、备注、代理、跳板机、高级终端配置以及 RDP/VNC/Telnet/串口专属配置按表单内容保存。
- 现有调用方不传新字段，因此新建、编辑、测试和导入链路保持兼容。

## 失败与回滚

- 源连接或源秘密缺失时，创建失败并在现有弹窗反馈区显示错误；不得静默创建不可连接的副本。
- 前端失败时保留复制弹窗和用户修改内容，允许修正或重试。
- 改动不涉及数据库迁移；代码回滚即可恢复旧行为，已创建的副本仍是普通连接记录。

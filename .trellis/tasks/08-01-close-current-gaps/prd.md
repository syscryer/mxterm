# 收敛当前产品与工程缺口

## Goal

收敛当前版本中已经确认的产品与工程缺口：让首页“导入连接”成为真实可用能力，以 MIT 许可证明确公开使用边界，并清理已经与代码事实不一致的 Trellis 活动任务和规范状态。

## Confirmed Facts

- 首页“导入连接”按钮当前实际调用连接列表刷新函数，属于误导性入口。
- 用户已选择为连接迁移建立独立的 `mxterm-connections` 加密 JSON 格式，不直接复用或扩展现有 `mxterm-sync` 同步快照格式。
- 首版导出范围固定为当前仓库的全部连接、连接分组、可复用账号及其凭据，不新增列表多选或单连接导出模式。
- 导出文件中的连接、分组和账号元数据保持可读；只有密码、私钥口令等敏感值进入加密载荷，不对整个 JSON 数据载荷加密。
- 首版不读取或打包私钥文件内容；只保留原私钥路径，并将对应私钥口令作为敏感凭据加密。导入设备无法访问原路径时必须在预检中提示。
- 当前 `npm test` 仍是占位命令；用户明确本任务不处理前端测试框架。
- 当前 GitHub Actions 只有发布 workflow；用户决定本任务暂不补充日常 CI 质量门禁。
- 当前仓库没有 `LICENSE`；用户已选择 MIT License。
- Windows Authenticode、macOS Developer ID 签名和 notarization 暂未接入；用户明确本任务不处理系统签名。
- 17 个活动 Trellis 任务中，多数已有对应实现提交；`mx-agent` 已迁移到独立仓库，mXterm 内只剩迁移指针；规范索引仍有多项 `To fill`。

## Requirements

- 为首页提供真实的批量连接导入流程；导入入口不得继续复用刷新动作，也不得静默覆盖现有连接或敏感凭据。
- 首版采用 mXterm 原生 JSON 格式，覆盖 SSH、RDP、VNC、Telnet、串口连接及连接分组，不支持第三方专有格式或 OpenSSH config。
- 同时提供连接与分组的本地 JSON 导出入口，形成可重复验证的导入/导出迁移闭环。
- 导出为全量仓库迁移操作；不得因首页当前筛选、搜索或单条选中状态而漏掉连接或依赖数据。
- 连接导入必须使用带格式名和版本号的稳定 schema，提供文件选择、解密、预检摘要、冲突策略、成功/失败反馈，并在成功后刷新连接仓库。
- 导出 JSON 包含连接、分组、可复用账号以及对应密码/私钥口令；所有敏感值必须使用用户本次输入的导出密码加密，不得以明文、可逆编码或保险库本地引用形式写入文件。
- 明文数据与加密凭据必须通过认证加密的关联数据绑定；篡改明文连接数据后，解密或预检必须失败。
- 导出密码不得写入应用设置、数据库、日志或导出文件；导入时由用户重新输入，密码错误或密文损坏必须在任何写入前失败。
- 导入不会复制、覆盖或删除任何私钥文件；私钥路径不可用属于可见警告，不阻止其他合法连接导入。
- 复用现有同步快照的 Argon2id 密钥派生与 AES-256-GCM 认证加密语义，不新增自定义密码学实现。
- 连接迁移格式与同步快照保持职责隔离：只共享经过测试的加解密基础能力，不继承同步快照中的设置、隧道、known hosts 或整体替换语义。
- 导入采用合并语义：先预检新增项和冲突项，默认跳过现有冲突；只有用户明确选择覆盖后才更新冲突项。
- 导入批次必须原子提交；字段验证、解密、引用校验或任一持久化步骤失败时不得留下部分导入结果。
- 在仓库根目录加入标准 MIT License，并更新 README 的许可说明。
- 基于当前代码、提交和任务验收证据清理 Trellis 状态：归档已完成的 mXterm 任务，归档仅保留迁移指针的 `mx-agent` 任务，保留真正未完成的规范建设任务。
- 更新规范索引，使 `Active` / `To fill` 状态与当前文档内容一致；不为了消除 `To fill` 而编造尚未形成的项目约定。
- 保留用户现有未提交文件，不修改 `.codex/config.toml`、`.opencode/` 和 `.tmp-dev/`。

## Acceptance Criteria

- [ ] “导入连接”打开真实导入流程，不再触发普通刷新。
- [ ] 首页仓库维护区同时提供真实的 JSON 导入与导出入口。
- [ ] 导入/导出文件使用带版本号的 mXterm JSON schema，可表达多协议连接、分组、可复用账号及其凭据。
- [ ] 导出文件不包含明文密码、私钥口令或本机保险库引用，且能使用正确导出密码恢复凭据。
- [ ] 修改导出文件中的受保护明文数据会导致认证或完整性校验失败，且不会进入写入阶段。
- [ ] 私钥文件内容不出现在导出包中；导入预检会列出当前设备不可访问的私钥路径。
- [ ] 错误密码、密文损坏、结构非法、重复项和冲突均有明确反馈，并在任何持久化写入前失败。
- [ ] 导入预检显示新增和冲突数量，默认跳过冲突，用户可明确改为覆盖冲突。
- [ ] 导入成功后新增/更新结果可在连接仓库中看到，取消或失败时不产生部分写入。
- [ ] release workflow 保持现有签名状态和发布行为，不新增证书依赖。
- [ ] 根目录存在 MIT `LICENSE`，README 不再声称许可证缺失。
- [ ] 已有实现证据的陈旧 Trellis 任务完成归档，跨仓库迁移指针任务完成归档，真正未完成任务继续保留。
- [ ] backend/frontend 规范索引状态经逐项核对，不再出现内容已落地但仍标记 `To fill` 的明显漂移。
- [ ] 项目要求的检查、构建和任务上下文验证通过。

## Out Of Scope

- 配置前端单元测试框架或改写 `npm test`。
- 新增或调整日常 CI 质量门禁。
- Windows Authenticode、macOS Developer ID 签名、Apple notarization 及相关凭据配置。
- macOS Intel 发布、非安装版自动更新、跨平台嵌入式 RDP。
- 团队共享、企业审计或第三方客户端的大规模专有格式迁移。
- 单连接导出、勾选后批量导出及分享链接。
- 私钥文件打包、托管、复制、重命名或自动清理。

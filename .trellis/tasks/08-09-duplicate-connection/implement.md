# 复制连接实施计划

## 1. 扩展请求契约与后端保存逻辑

- 在 TypeScript 与 Rust 的 `ConnectionProfileInput` 中增加可选 `source_connection_id`，保持字段命名和序列化一致。
- 在存储仓库中校验复制来源仅用于新建连接，并读取源连接及其秘密引用。
- 扩展内联秘密准备逻辑：未修改秘密时从源槽位复制到新连接槽位；用户修改时沿用现有保存逻辑。
- 让临时连接测试在复制草稿下也能从 `source_connection_id` 解析源秘密。
- 增加 Rust 单元测试，覆盖密码、私钥口令、保存账号引用、运行状态重置、源连接缺失及副本独立性。

## 2. 接入复制弹窗模式

- 为 `ConnectionDialog` 增加显式复制模式，复用现有预填、密码查看和校验逻辑。
- 生成唯一的默认副本名称，清除 ID、收藏、连接时间和远端探测字段，并设置 `source_connection_id`。
- 调整复制模式的标题、提交按钮和删除入口；取消时不得保存。
- 保证复制弹窗修改密码后保存新值，未修改时由后端复制原秘密。

## 3. 增加左侧右键入口

- 为 `ConnectionPane` / `ConnectionTreeLeaf` 增加最小的 `onDuplicate` 回调链。
- 在现有共享右键菜单中加入 Lucide `Copy` 图标和“复制连接”文案，位置在编辑与收藏之间。
- 在 `WorkspaceShell` 接线并继续通过现有动态导入预热连接弹窗。
- 不修改首页表格操作列和表格行交互。

## 4. 验证

- 运行 Rust 格式化与相关单元测试，确认秘密复制和连接独立性。
- 运行 `npm run check` 与 `npm run build`。
- 运行 `node scripts/check-startup-module-boundary-source.mjs`，确认连接弹窗和其他重模块未进入首屏静态依赖。
- 人工验证亮色、显式暗色和 system-dark：菜单位置、复制弹窗文案、取消无副本、创建后可连接、密码查看、修改与删除互不影响。
- 检查 `git status --short` 和任务范围 diff，确保未包含现有 `.codex/config.toml`、`.opencode/`、`.tmp-dev/` 等无关改动。

## 风险点与回滚点

- 风险集中在内联秘密复制；先完成仓库层测试，再接 UI。
- 不增加数据库迁移或新依赖，任一步失败可按文件回退，不需要数据回滚。
- 若秘密复制测试未通过，不得用空密码、自动显示密码或前端静默兜底交付。

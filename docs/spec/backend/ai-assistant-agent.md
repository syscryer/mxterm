# AI 助手 Agent 契约

## 工作区

Agent 每次运行必须明确当前终端主机，并可选绑定独立的本地文件工作区：

- 当前主机：保存的 SSH 连接，或当前本机终端。
- 本地文件工作区：用户明确选择的本地目录，可在 SSH 主机运行时单独启用。

命令、监控、后台任务和终端上下文必须跟随当前终端主机；文件工具省略目标时也跟随当前终端主机。SSH 会话未指定工作区且当前终端目录不可用时，后端在当前 SSH 主机上解析登录用户的真实家目录作为默认工作区；SSH 会话只有在工具参数明确传递 `target=local` 时才使用本地文件工作区；本机终端默认使用本机当前目录。后端不得根据模型输入猜测或切换主机。

工作区是默认目录和编码上下文，不是文件访问沙箱。本地与 SSH 的读取、搜索、补丁、创建、覆盖、删除、重命名及回滚都允许访问当前目标主机上的其它路径：相对路径（包括 `..`）按该目标的工作区解析，绝对路径直接使用，实际访问权限由目标主机的登录用户决定。读快照、待应用变更和回滚索引继续按主机与会话隔离；目录放开不改变模式审批、CAS、备份、原子替换或审计规则。SSH 搜索不得依赖无关的默认目录存在；绝对搜索路径只校验和访问该路径。

## 工具与权限

Agent 工具分为只读、需确认和用户输入三类。`execute` 模式下危险命令进入 `pending_approval`；`full` 模式跳过普通危险命令确认，只有递归删除主机根目录（包括 `--no-preserve-root` 形式）在执行前拒绝。审批结果由用户界面写入，模型不能自我批准。`ask_user` 使用独立的 `pending_user_input` 状态，可携带结构化 `options`、`allow_free_text`，用户回答通过独立的答案命令回传，不复用命令审批。

SSH 文件搜索优先调用 `rg`，不可用时回退到 `find` / `grep`。搜索命令不额外截断结果，不隐藏搜索错误；模型上下文和审计预览沿用统一的输出大小规则。

联网搜索使用独立的只读 `web_search` 工具，返回标题、摘要和来源 URL；`web_fetch` 用于读取公开 HTTP(S) 页面正文，并通过 `start_index` 继续读取过长内容。联网请求在 mXterm 本机网络环境执行，不跟随当前 SSH 主机，也不通过 `run_command` 间接执行 curl。网页读取拒绝本机、内网和非 HTTP(S) 地址；网络错误、HTTP 错误和响应超限必须原样进入工具失败状态和审计记录。

文件修改必须先生成带上下文的 diff。`read_file` 支持按行分段读取，但只有完整读取后的文件才能进入编辑状态；`preview_patch` 默认要求唯一匹配，也支持明确的 `replace_all`；完整覆盖使用文件写入预览。应用修改前重新读取文件并校验旧内容；文件发生变化时拒绝写入。写入使用备份和原子替换，保留原文件换行和权限，远程文件复用现有 SFTP 编辑限制并检查每个远程命令退出码。完全访问模式下文件操作不再重复弹出确认，但仍保留 diff、CAS、备份和审计。

同一聊天会话的后续 Agent 回合会复用已读取快照、待应用变更和回滚索引；这些记录持久化到 SQLite，重启后仍可撤销已记录的修改。清空或删除会话时一并清理索引；恢复或反序列化失败必须显式报错，不能用空索引覆盖原记录。

### 自动文件检查点与撤销

每次成功的文件应用统一记录实际应用时间及单调递增顺序，并归入当前 assistant 消息的自动检查点。预览、拒绝和失败不能计入。检查点保留原始文件版本、默认目录、SSH 连接及主机/端口/用户身份，不保存 SSH 凭据；撤销重新获取凭据并核对原主机身份，不使用当前焦点终端。创建检查点和整轮回滚不再作为模型公开工具，旧调用仍可兼容执行。

`ai_chat_session_get` 返回每条回复的 `file_changes`；`file_changes` 流事件在索引保存成功后发送。汇总对同一主机文件的首个 before 与最后 after 计算净增删行数；本机与 SSH 同名路径分别统计。重命名按原路径移除与目标路径创建展示。旧索引缺少回复归属时不补造每轮检查点。

`ai_file_changes_undo` 校验会话、回复与检查点归属，拒绝仍有活动 Agent 的会话；与启动、清空、删除共用操作锁。先模拟逆序恢复并校验所有当前版本，已知冲突时不修改任何文件；同一文件的后续回复修改必须先撤销。执行时逐项再次 CAS 校验，并在每次成功后持久化真实剩余状态。运行期错误允许部分完成，返回已撤销数、剩余数及具体错误，不能显示整体成功。对话记录不回退。通过 shell 命令写入的文件未进入文件索引，不属于此功能的自动撤销范围。

`preview_patch` / `preview_file_change` 成功生成预览后即为 `completed`，不创建审批等待；模型继续调用应用工具，`apply_patch` / `apply_file_change` 才按权限模式进入真实审批或执行。文件记录附带可选 `file_activity`（真实路径、操作、重命名目标、增删行数），应用及回滚的元数据来自当前会话的变更索引，不从内部编号猜测。行数按展示的 diff 变更区间计算；重命名不显示文本增删数。加载旧历史时仅修正误标为 `pending_approval` 的预览记录，并记录修正数量；不改变实际应用、命令的审批状态，也不补造历史完成时间。

后台任务返回稳定的任务 ID，支持查询状态、读取有界输出和取消。任务取消必须终止本地子进程或关闭远程执行通道。前台 `run_command` 与后台 `start_task` 共用输出事件；`run_command` 传入 `background=true` 时转入后台，输出实时推送到同一条工具记录。命令结束后完整 stdout/stderr 写入会话 artifact，任务状态和 artifact 编号持久化，并发送完成事件；应用重启后不会伪造恢复中的运行态。

## 执行生命周期

Agent 不设置固定工具调用轮次上限。模型继续返回工具调用时，执行工具并将真实结果交回模型；模型不再请求工具时结束本次回复。每轮模型请求前及每个工具执行前检查用户停止状态，接口或审计错误按原错误流程结束。

## 审计

每次工具调用至少记录工具 ID、名称、工作区、连接、命令或文件路径、风险、审批结果、状态、开始/结束时间、退出码、输出截断标记和错误。日志内容需要限制大小并避免保存凭据。

## 消息附件

用户消息可以携带图片和文本类文件上下文。图片使用 `data_url` 传入，支持 PNG、JPEG、GIF、WebP，单张不超过 12 MB，单次最多 4 张；后端先校验 MIME 声明、Base64 解码结果和文件签名，再保存为当前会话的 Artifact。文本文件使用 `kind=file` 和完整 UTF-8 `content` 传入，不设置单个文件的固定大小上限，单次最多 8 个；后端保存完整 UTF-8 内容到会话 Artifact，消息只持久化文件元数据、有限预览和 Artifact 编号。模型上下文只发送附件元信息和预览，完整内容通过 `read_attachment` 使用 `attachment_id` 与 `offset/limit` 按需读取。

普通聊天和 Agent 请求都必须把已校验的附件带入模型请求：OpenAI 兼容格式使用 `image_url`，Responses 使用 `input_image`，Anthropic 使用 base64 image block；图片在请求模型时从会话 Artifact 恢复，数据库和历史消息不保存 Base64。文本附件通过 `read_attachment` 按需进入工具结果。历史消息恢复时保留附件元数据和 Artifact 编号，用户打开预览时再读取完整内容；上下文压缩只保留附件占位信息，不把 Base64 或完整文本写入摘要。

## 验收

1. 本机和 SSH 远程终端都能执行验证命令；本地文件工作区可独立读取和搜索内容。
2. 本地和 SSH 都能读取、搜索和修改工作区外的路径；相对路径默认按工作区解析，文件被外部修改后旧 diff 仍不能覆盖，回滚仍只接受当前会话拥有的变更。
3. `execute` 模式下危险命令必须二次确认；`full` 模式直接执行危险命令，仅递归删除主机根目录仍被拒绝。
4. 长命令可后台运行、查询输出并取消。
5. 聊天历史能恢复工具调用和审批后的最终状态。

## 实施计划

按以下顺序逐项实现，每项完成后先验证再进入下一项：

- [x] **实时终端输出**：为终端会话增加有界 ring buffer、游标和截断信息，并绑定连接与会话。
- [x] **文件生命周期操作**：补齐 rollback、create、delete、rename，统一 diff、版本校验、备份和主机隔离。
- [x] **工作区目录语义**：本地和 SSH 工作区仅作为默认目录与编码上下文，允许当前主机上的其它路径，保留审批、CAS、备份与回滚归属校验。
- [x] **每轮文件修改与撤销**：自动检查点、净增删汇总、按应用顺序逆序恢复、重启后保留索引及冲突校验；6 项后端回归和界面交互验证已通过。真实 SSH 连接的重启后撤销仍需桌面验收。
- [x] **后台任务管理**：持久化任务状态、输出和时间；应用重启后标记 interrupted；本地任务可真实终止，远程任务明确停止确认边界。
- [x] **审计日志界面**：增加查看、筛选和导出入口，确保 command、output、token、credential 脱敏。
- [x] **Agent 计划与提问 UI**：为 update_plan 和 ask_user 增加专用展示、确认和状态。
- [x] **安全回归**：完成目标主机隔离、CAS 冲突、高危命令确认、审计失败即停、任务取消状态和前端/后端构建回归。

每一项都必须有可观察状态和验证结果，未完成的操作不能在界面显示为成功。
